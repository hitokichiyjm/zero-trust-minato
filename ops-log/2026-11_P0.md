## つまずいたことと対応
| # | 起きたこと | 原因 | 対応 |
|---|---|---|---|
| 1 | サインアップでプロジェクトの画面になった | 2026年9月からの新しいサインアップ(Builder ID)に入っていた。ルートユーザーがなく、SCP を自分で書けない | 「Sign up for AWS (advanced)」で作り直した |
| 2 | 漏えいの試験で、偽のキーのコミットが止まらなかった | AWS のドキュメントの例のキー(`...EXAMPLE`)は gitleaks がわざと除外している | ランダムに作った偽のキーで試験するように手順を直した |
| 3 | IAM ロールの作成に失敗 | IAM の description に日本語が使えない | 英語にした |
| 4 | 状態ファイルの移行に失敗 | `backend.tf` を置いた後に `terraform output` を実行し、バケット名が空になった | 手順の順番を直した |
| 5 | `git push` が拒否された | GitHub CLI のトークンに `workflow` の権限がなかった | `gh auth refresh -s workflow` |
| 6 | GitHub Actions で AssumeRoleWithWebIdentity が拒否された | GitHub の OIDC の `sub` が、ID を含む形式(immutable subject)だった | 信頼条件を ID を含む形にした。同じ名前で作り直されたリポジトリからのなりすましも防げる |
| 7 | CI の plan だけ「1 to add」になった | 既存のコスト異常モニターを使う設定が、手元の tfvars にしかなかった | 既存のモニターを import してコードで管理した |
